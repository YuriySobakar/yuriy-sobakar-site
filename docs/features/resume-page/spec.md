# Spec — resume-page

> **Glossary:** [CONTEXT](../../../CONTEXT.md)
> **Reference module / docs / channels used:** старий сайт `C:\Users\Admin\Desktop\RESUME project\src\Index.html` (структура секцій, факти, контакти); `docs/idea-brief.md`, `docs/roadmap.md` (крок 4), `docs/architecture-map.md`; робочі репозиторії власника за останній рік як джерело фактів про досвід: `/root/web` (Nutrition for Living), `/root/myorcare/web`, `/root/projects/tomatoes`, `D:\Mate-Academy\Tailwind-practice\adflagger_project`.

## 1. Context

Чинний сайт-візитка власника (2024) не адаптується під телефон, не оновлювався понад рік і подає застаріле позиціювання. Recruiter, який відкриває посилання з резюме чи LinkedIn — найчастіше з телефона — не може за 30 секунд зрозуміти, хто перед ним, і не має зручного способу написати. Hiring manager не бачить реального комерційного досвіду останнього року (дочірні теми для клієнтів, автоматизація, інфраструктура) і проєктів із живими посиланнями. Site owner не оновлює сайт, бо кожна правка означає правку верстки.

Тригер — збіг двох подій: рік без оновлень, за який досвід суттєво виріс, і воркшоп з agentic engineering 5 вересня 2026, що дає процес зробити оновлення системно. Пошук роботи з чинною сторінкою шкодить.

Підхід: сторінка як **безпечне подання даних**. Весь текст береться з одного файлу resume data; перший екран веде до контакту (ім'я, позиціювання, 1–3 факти, контакти); порожня section чи група не показується; без обов'язкових полів публікація блокується з поясненням власнику; досвід упорядковується за датою початку від найновішого, проєкти і групи навичок — у порядку, заданому в resume data; commercial project показується з назвою, галуззю, живим посиланням, стеком, роллю і результатом, але ніколи з посиланням на код (код робочих репозиторіїв — комерційна таємниця); pet project показується з посиланням на код; опційна позначка confidential project ховає назву клієнта і посилання на випадок майбутнього NDA. Дослідження суміжних рішень (екосистема резюме-як-дані, шаблони портфоліо, конструктори резюме) показало, що жодне з них не дає саме цієї publish-safety логіки — це і є відмінність фічі. Найгостріший вектор відмови за оцінкою адвоката диявола — витік назви клієнта через забуту позначку — закрито структурно: секрет лише код, і посилання на код у commercial project заборонене правилом, а не позначкою.

Трасування: перелік секцій, факти й контакти успадковано зі старого сайту (заголовок «Full-Stack WordPress Developer | Tech SEO Specialist», секції Work Experience / Tech Skills / Contacts, контакти пошта / Telegram / LinkedIn / телефон); позиціювання й правила з `docs/idea-brief.md` §6–§7; факти про досвід останнього року — з робочих репозиторіїв, названих вище. Decision override: позначка confidential лишається опційною, а не «безпечним дефолтом» — rationale: власник підтвердив, що проєкти і їх стек не є таємницею, таємниця — тільки код, який заборонений для commercial project правилом.

## 2. Goals

- Recruiter з телефона за 30 секунд розуміє позиціювання власника і має контакт у один дотик — сторінка веде до звернення, а не до читання.
- Hiring manager перевіряє комерційний досвід за живими посиланнями та вектор зростання за pet project з кодом.
- Site owner оновлює сторінку лише правкою resume data, а небезпечні стани (порожні обов'язкові поля, код commercial project, розкритий confidential project) не доходять до публікації.

## 3. Non-goals

- Друковане подання і кнопка «Download PDF» — окрема наступна фіча (roadmap крок 5); ця сторінка лише не заважає їй: жоден зміст із resume data не прихований за взаємодією (наведення, розгортання, вкладки, карусель, прокрутка всередині блоку) — усе видно на одній прокручуваній сторінці.
- Службові підписи інтерфейсу (підписи кнопок-посилань на кшталт «Сайт» / «Код», префікси на кшталт «Стек:», тексти для екранних читачів, слово «дотепер» у періоді) — частина шаблону, не resume data; їх зміна — правка шаблону.
- Блок «як зроблено цей сайт» — окрема фіча (roadmap крок 6).
- Фінальна візуальна концепція («цікавіший дизайн») — ще не сформульована (roadmap, fog); сторінка будується на базових дизайн-токенах, які концепція потім замінить без переверстки.
- Блог, контактна форма, українська версія, сторінки-кейси, адмінка — поза скоупом продукту (`docs/idea-brief.md` §5).
- Наповнення resume data реальним змістом — roadmap крок 2; ця фіча визначає, що і як показується, а не сам текст.

## 4. User stories

### US-01: Перший екран веде до контакту

**As a** recruiter
**I want** відкривши сторінку з телефона, побачити до прокрутки ім'я, позиціювання, 1–3 ключові факти і контакти
**So that** за 30 секунд зрозуміти, хто це, і написати одним дотиком

### US-02: Досвід від нового до старого

**As a** recruiter
**I want** переглянути досвід у зворотному хронологічному порядку з роллю, компанією, періодом і результатами
**So that** оцінити релевантність останніх ролей, не читаючи всю сторінку

### US-03: Навички групами і проєкти з посиланнями

**As a** hiring manager
**I want** бачити навички згруповано за категоріями і проєкти з живими посиланнями, а для pet project — ще й посилання на код
**So that** перевірити стек і якість роботи, а не вірити списку слів

### US-04: Оновлення без верстки

**As a** site owner
**I want** змінювати весь зміст резюме (ім'я, позиціювання, факти, досвід, навички, проєкти, контакти) та заголовки section лише правкою resume data
**So that** оновлення займало хвилини і сайт не застигав знову

### US-05: Захист від порожнього і зламаного

**As a** site owner
**I want** щоб без обов'язкових полів сторінка не публікувалась, а порожня section не показувалась порожньою
**So that** recruiter ніколи не побачив сторінку без імені, контактів або з голими заголовками

### US-06: Конфіденційний проєкт не розкривається

**As a** site owner
**I want** позначити commercial project як confidential project і бути впевненим, що назва клієнта й посилання не потраплять на сторінку
**So that** майбутнє NDA не вимагало переробки сторінки

### US-07: Читається з телефона

**As a** recruiter
**I want** читати сторінку на телефоні без горизонтальної прокрутки й масштабування
**So that** не витрачати зусиль на читання і не закрити вкладку

## 5. Acceptance criteria

### AC-01 (US-01) — happy path

**Given** resume data містить ім'я, позиціювання, 1–3 факти і принаймні один контакт
**When** recruiter відкриває сторінку на телефоні з екраном 360×640 CSS-пікселів
**Then** до будь-якої прокрутки recruiter бачить ім'я, позиціювання, усі факти (1–3) і контакти

### AC-02 (US-01) — happy path

**Given** у resume data вказані пошта, Telegram і LinkedIn власника
**When** recruiter торкається одного з контактів
**Then** відкривається відповідний застосунок або сторінка з адресою власника вже підставленою, без ручного копіювання

### AC-03 (US-02) — happy path

**Given** resume data містить кілька записів досвіду з датами
**When** recruiter переглядає section «досвід»
**Then** записи йдуть від найновішого до найстаршого за датою початку; запис без дати закінчення показується як «дотепер»; кожен запис показує роль, компанію, період і принаймні один результат

### AC-03b (US-02, US-05) — domain invariant violation

**Given** у resume data запис досвіду без ролі, компанії, дати початку або без жодного результату
**When** site owner публікує зміни
**Then** система блокує публікацію і повідомляє site owner назву запису та порожнє поле (там само, де запущено публікацію — як в AC-07)

### AC-04 (US-03) — happy path

**Given** resume data містить навички, розбиті на групи, у заданому порядку
**When** hiring manager переглядає section «навички»
**Then** навички показані групами в тому самому порядку, без рівнів, відсотків чи шкал

### AC-05 (US-03) — domain invariant violation

**Given** у resume data для commercial project заповнене поле «посилання на код» АБО будь-яке його посилання веде на сервіс хостингу коду (GitHub, GitLab, Bitbucket та інші зі списку, який фіксує `design`)
**When** site owner публікує зміни
**Then** система блокує публікацію і повідомляє site owner назву проєкту та правило «код commercial project не публікується» (там само, де запущено публікацію — як в AC-07)

### AC-06 (US-06) — authorization

**Given** commercial project позначений як confidential project
**When** recruiter або hiring manager відкриває сторінку будь-яким способом, включно з переглядом її вихідного тексту
**Then** видно лише галузь, роль і результат; назва клієнта і будь-які посилання проєкту відсутні на сторінці повністю

### AC-07 (US-05) — error

**Given** у resume data порожнє обов'язкове поле — ім'я, позиціювання, жоден контакт не заповнено, немає жодного факту (або фактів більше трьох), або в commercial project не вказана галузь
**When** site owner публікує зміни
**Then** система блокує публікацію і повідомляє site owner, яке саме поле обов'язкове і порожнє (чи перевищене); пояснення з'являється в тому самому місці, де site owner запустив публікацію, як її безпосередня відповідь — публікація не може бути відхилена мовчки

### AC-08 (US-05) — domain invariant violation

**Given** одна з section у resume data, або група всередині section (наприклад, група навичок), не містить жодного запису
**When** recruiter відкриває сторінку
**Then** ця section чи група не показується взагалі — ні заголовок, ні вміст; section, у якій усі групи порожні, теж не показується; решта показані без змін

### AC-09 (US-04) — cross-context

**Given** сторінка вже опублікована, і site owner публікує resume data, що порушує будь-яке правило вище
**When** публікація відхилена
**Then** відвідувачі продовжують бачити попередню опубліковану версію повністю (ніколи порожню чи часткову), а site owner отримує пояснення помилки там, де запустив публікацію (як в AC-07)

### AC-10 (US-07) — happy path

**Given** recruiter відкриває сторінку на екрані шириною 360 пікселів
**When** прокручує всі section
**Then** жодна section не потребує горизонтальної прокрутки чи масштабування; основний текст не менше 16 CSS-пікселів, допоміжний (періоди, підписи) — не менше 14

### AC-11 (US-04) — happy path

**Given** сторінка вже опублікована
**When** site owner змінює будь-який зміст резюме (наприклад, результат у записі досвіду) лише у resume data і публікує
**Then** на живій сторінці новий текст з'являється дослівно, а жоден інший файл проєкту при цьому не змінювався

## 6.1 Security / privacy

- **Data classification:** public — усе на сторінці власник свідомо публікує для найму.
- **Personal data touched:** лише дані власника: ім'я, пошта, Telegram, LinkedIn, місто; телефон — під питанням (§8). Чужих персональних даних немає.
- **AuthZ/AuthN impact:** немає — сторінка лише для читання; змінювати resume data може лише site owner через репозиторій.
- **Abuse cases:**
  - збір пошти спамерами: приймаємо як ціну прямих контактів; телефон не публікуємо, поки не вирішено інакше (§8).
  - розкриття коду клієнта: посилання на код у commercial project заборонене правилом і блокує публікацію (AC-05), незалежно від позначок.
  - розкриття клієнта під NDA: confidential project ховає назву і посилання повністю, включно з вихідним текстом сторінки (AC-06).
  - шкідлива розмітка в resume data: текст із даних ніколи не виконується як розмітка чи скрипт — показується як текст.
  - мертві посилання проєктів: recruiter бачить непрацюючий проєкт — перевірка при публікації винесена в §8.
  - стеження за відвідувачами через лічильник кліків: лічильник не збирає персональних даних (без cookie, без ідентифікаторів відвідувача), рахує лише події; його вага входить у бюджет §6.
- **Security review:** N/A — статична сторінка без авторизації, без чужих даних, без власної серверної логіки (окрім лічильника кліків, що не збирає персональних даних).

## 7. Metrics / KPIs

- **Кліки по контактах на 100 візитів** — baseline: 0 (на старому сайті аналітики немає), target: ≥ 10 протягом 60 днів після публікації. План вимірювання: легкий лічильник кліків по контактах без важкої аналітики; інструмент обирає `design`.
- **PageSpeed Insights mobile Performance** — baseline: показник старого сайту, заміряти в день запуску, target: ≥ 95 на кожному релізі.
- **Час оновлення змісту** — baseline: години правки HTML на старому сайті, target: ≤ 5 хвилин від правки resume data до живої сторінки на перших трьох оновленнях (збігається з §6).
- **Свіжість** — baseline: 12+ місяців без оновлень, target: resume data оновлюється щонайменше раз на квартал (за історією змін репозиторію).
