# 0002 — Віддавати шаблонам безпечне подання даних (view model), а не сирий resume data

- **Status:** Accepted
- **Date:** 2026-09-05
- **Deciders:** Yuriy Sobakar + SDD design (Socratic walk, depth easy)

## Context

Шаблони мають показувати confidential project без назви клієнта і без посилань навіть у вихідному коді сторінки (AC-06), упорядковувати досвід за датою початку від найновішого (AC-03), не показувати порожні section і групи (AC-08), а проєкти й групи навичок виводити в порядку з resume data (AC-04). Ці правила потрібні кожному партіалу, включно з майбутніми (друковане подання, крок 5; блок «як зроблено», крок 6). Треба вирішити, де ця логіка живе: у коді підготовки даних чи в шаблонах Nunjucks.

## Decision drivers

- Спека §6.1, abuse case «розкриття клієнта під NDA»: назва і посилання відсутні повністю, включно з view-source.
- Оцінка адвоката диявола у спеці §1: найгостріший вектор відмови — витік через забуту умову.
- Карта архітектури §Conventions: кожна секція — окремий партіал; партіалів буде більше.
- Тестованість: `node --test` без браузера, бажано без повної збірки.

## Considered options

1. **Безпечне подання даних** — data extension Eleventy повертає шаблонам уже підготовану модель: у confidential project назва і посилання відсутні як поля, досвід відсортований, порожні section і групи прибрані, дати відформатовані. Шаблони лише виводять отримане.
2. **Логіка в шаблонах** — шаблони отримують сирий YAML і самі вирішують умовами `{% if %}` та фільтрами Nunjucks (приховування, сортування, перевірка на порожнє).

## Decision outcome

**Chosen:** Option 1. Секрет фізично не існує в шаблонному контексті, тому жоден новий партіал не може його вивести випадково; сортування і прибирання порожнього стають функціями з юніт-тестами. Варіант «логіка в шаблонах» відкинуто, бо кожен новий партіал мусив би повторювати ті самі умови, а одна забута умова означає назву клієнта у вихідному коді сторінки, і перевірити це можна лише збіркою та читанням HTML.

## Consequences

**Positive**
- AC-06 виконується структурно, а не позначкою в шаблоні; test збірки додатково шукає назву confidential project у HTML як другий бар'єр.
- Шаблони прості: цикл і вивід; правити вигляд може людина без знання правил.
- Друковане подання (крок 5) отримує ті самі безпечні дані без додаткової роботи.

**Negative**
- Близько 100–150 рядків коду в `lib/resume/view-model.js` замість звичних умов у шаблонах.
- Усе, що шаблон хоче показати, має бути явно додане в подання; сирі дані шаблону недоступні.

**Neutral**
- Форма подання може розширюватись (нові обчислені поля) без зміни resume data.
