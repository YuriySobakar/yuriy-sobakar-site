# 0003 — Рахувати кліки по контактах легким стороннім лічильником подій без cookie, як виняток із правила «без клієнтського JavaScript»

- **Status:** Accepted
- **Date:** 2026-09-05
- **Deciders:** Yuriy Sobakar + SDD design (Socratic walk, depth easy)

## Context

Спека §7 ставить KPI «кліки по контактах на 100 візитів ≥ 10 протягом 60 днів» і в §8 залишає вибір інструмента за design; §6.1 уже дозволяє лічильник, який не збирає персональних даних (без cookie, без ідентифікаторів відвідувача) і чия вага входить у бюджет 150 КБ. Водночас конвенція фундаменту каже: «без клієнтського JavaScript, окрім `window.print()`; будь-яка інтерактивність понад це потребує ADR» (карта архітектури, §Conventions). Це той ADR.

## Decision drivers

- Спека §7 KPI: без лічильника ціль неперевірювана, а baseline на момент запуску втрачається назавжди.
- Спека §6 NFR: PageSpeed Insights mobile ≥ 95 і ≤ 150 КБ переданих байтів, лічильник входить у бюджет.
- Спека §6.1: без cookie і без ідентифікаторів відвідувача, тобто без банера згоди.
- Карта архітектури §Constraints: без серверного коду, статичний хостинг.

## Considered options

1. **Легкий сторонній лічильник подій без cookie** (наприклад GoatCounter: відкритий код, безкоштовний для особистих сайтів, скрипт близько 3–4 КБ, підключається асинхронно) плюс короткий inline-обробник, який при кліку по контакту надсилає подію на кшталт `contact:email`.
2. **Без лічильника в цій фічі** — сторінка лишається без клієнтського JS окрім друку; KPI §7 не вимірюється, вимірювання виноситься окремою фічею.

## Decision outcome

**Chosen:** Option 1. KPI вимірюється з першого дня, сторінка працює без скрипта, якщо сервіс недоступний (скрипт асинхронний і не блокує рендер), вага вміщується в бюджет. Варіант «без лічильника» відкинуто, бо ціль спеки стає неперевірюваною, а baseline втрачається. Виняток із конвенції «без JS» обмежений рівно одним тегом скрипта і одним обробником кліків у `layout.njk`; будь-який інший клієнтський код і далі потребує окремого ADR.

## Consequences

**Positive**
- KPI §7 має інструмент виміру з дня запуску; дашборд лічильника показує події по типах контактів.
- Без cookie і персональних даних, отже без банера згоди і без впливу на конвенцію приватності зі спеки §6.1.
- Вимкнути лічильник = видалити один тег і один обробник.

**Negative**
- Залежність від стороннього сервісу і акаунта в ньому; якщо сервіс зникне, дані подій треба експортувати.
- Другий дозволений скрипт на сторінці після `window.print()`; при кожному релізі перевіряємо, що PageSpeed Insights не просів.

**Neutral**
- Заміна на інший лічильник без cookie — заміна тегу і обробника, дані про минуле не переносяться автоматично.
