# 0003 — Писати стилі чистим CSS з кастомними властивостями і окремим print.css

- **Status:** Accepted
- **Date:** 2026-09-05
- **Deciders:** Yuriy Sobakar + SDD survey (foundation session)

## Context

Сайт має бути адаптивним, «цікавішим» за старий і водночас перетворюватися на строге резюме при друку. Головний компроміс інтерв'ю — екранний дизайн проти друкованої версії — вирішено як «один зміст, два подання». Потрібен підхід до стилів, який тримає обидва подання під контролем без додаткової збірки.

## Decision drivers

- Друкована версія — окреме, повністю контрольоване подання (бриф §6, §7).
- Без додаткового кроку збірки поверх Eleventy (розмір XS, профіль Pro).
- Дизайн-токени в одному місці, щоб «цікавий дизайн» не розповзався по файлах.
- Власник володіє CSS і Sass; сучасний CSS (grid, nesting, custom properties) покриває потреби Sass.

## Considered options

1. **Чистий CSS з кастомними властивостями + окремий `print.css`** — токени, mobile-first розкладка, `@media print` в окремому файлі.
2. **Sass/SCSS** — змінні, міксини, розбиття на файли; потребує компіляції в пайплайні Eleventy.
3. **Tailwind CSS** — утилітарні класи в HTML; потребує збірки, друковані стилі через `print:`-префікси засмічують шаблони.

## Decision outcome

**Chosen:** Option 1. Нативні кастомні властивості дають токени, `@media print` в окремому файлі дає повний контроль над друком, а збірки стилів не потрібно взагалі. Sass відкинуто як зайвий крок збірки для однієї сторінки; Tailwind — через збірку і незручність друкованих стилів у шаблонах.

## Consequences

**Positive**
- Нуль інструментів для стилів; Eleventy просто копіює CSS.
- Друковане подання ізольоване в `print.css` і перевіряється окремо (Print preview).
- Токени в `tokens.css` — єдине місце для палітри, відступів, типографіки; темна тема додається через `prefers-color-scheme` без переробки.

**Negative**
- Без препроцесора немає міксинів і функцій; повторення доводиться тримати дисципліною.
- Правило «дизайн не спирається на те, що не друкується» треба перевіряти вручну на кожній зміні вигляду.

**Neutral**
- Додати PostCSS чи Sass пізніше можливо як окремий крок збірки, токени лишаються ті самі.
