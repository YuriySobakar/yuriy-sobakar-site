# 0002 — Зберігати весь зміст сайту в одному YAML-файлі з JSON Schema

- **Status:** Accepted
- **Date:** 2026-09-05
- **Deciders:** Yuriy Sobakar + SDD survey (foundation session)

## Context

Інтерв'ю зафіксувало головний ризик: сайт не оновлюється, якщо оновлення вимагає правки верстки. Потрібне одне місце, де живуть досвід, навички, проєкти й контакти, і яке власник править кілька разів на рік за хвилини — руками або через AI-агента. Водночас помилка в даних не повинна тихо зникати зі сторінки.

## Decision drivers

- Одне джерело правди для екранної та друкованої версії (бриф §7).
- Правка «за 5 хвилин» без дотику до HTML (бриф §3 «власник сайту», §6 ризик застигання).
- Помилка має ламати збірку з зрозумілим повідомленням, а не публікувати порожню секцію.
- Кейси-сторінки поза скоупом (бриф §5) — довгі тексти на проєкт не потрібні.

## Considered options

1. **Один YAML-файл + JSON Schema** — читабельний текст із коментарями, схема перевіряється тестом і під час збірки.
2. **Один JSON-файл** — Eleventy читає без налаштування; строгий синтаксис, без коментарів і багаторядкового тексту.
3. **Набір Markdown-файлів** (по одному на місце роботи і проєкт) — зручно для довгих описів; десяток файлів замість одного джерела.

## Decision outcome

**Chosen:** Option 1. YAML читається і правиться людиною без лапок і ком, підтримує коментарі та багаторядкові описи; JSON Schema поруч дає контракт полів, який ловить опечатки на етапі тесту/збірки. JSON відкинуто через незручність ручної правки, Markdown-набір — через розмивання єдиного джерела і відсутність потреби в довгих текстах.

## Consequences

**Positive**
- Оновлення сайту = правка одного файлу `src/_data/resume.yaml`; сайт і PDF змінюються синхронно.
- Схема документує структуру даних і захищає від тихих помилок.
- AI-агент може безпечно оновлювати дані: тест схеми — його зворотний зв'язок.

**Negative**
- Два файли треба тримати узгодженими: нове поле додається і в схему, і в YAML.
- Потрібне підключення YAML до Eleventy (одна залишкова залежність для парсингу YAML і одна для валідації схеми).

**Neutral**
- Перехід на кілька файлів (наприклад, окремо `projects.yaml`) — механічний, якщо файл розростеться.
