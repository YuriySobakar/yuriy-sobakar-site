# 0004 — Віддавати PDF через друковані стилі та системний друк браузера

- **Status:** Accepted
- **Date:** 2026-09-05
- **Deciders:** Yuriy Sobakar + SDD survey (foundation session)

## Context

Власник хоче «можливість експорту в PDF для роздрукування». Варіантів реалізації три, і вони по-різному впливають на збірку, залежності та ризик розходження PDF із сайтом.

## Decision drivers

- Одне джерело правди: PDF завжди відповідає сайту (бриф §7).
- Без серверного коду і важких залежностей у збірці Netlify (статичний хостинг, XS).
- Без клієнтського JavaScript понад мінімум (карта архітектури, §Constraints).
- Кирилиця і шрифти мають друкуватися коректно.

## Considered options

1. **Друковані стилі + кнопка «Download PDF», що викликає `window.print()`** — браузер сам зберігає PDF з друкованого подання.
2. **Готовий PDF генерується при збірці** безголовим браузером і публікується як файл.
3. **PDF збирається в браузері бібліотекою** з даних сторінки.

## Decision outcome

**Chosen:** Option 1. Нуль залежностей, PDF завжди актуальний, шрифти й кирилиця — як у браузері. Генерацію при збірці відкинуто через важку залежність (браузер ~300 МБ) і довший деплой; її можна додати пізніше поверх цього рішення, бо друковане подання вже існуватиме. Клієнтську бібліотеку відкинуто через другу розкладку, що розходиться з сайтом, і JS на сторінці.

## Consequences

**Positive**
- Немає що обслуговувати: працює в будь-якому браузері через стандартний діалог друку.
- Друковане подання — це той самий HTML, розходження неможливе.

**Negative**
- Рекрутер тисне «Зберегти як PDF» сам, а не отримує готовий файл за посиланням.
- Вигляд PDF трохи залежить від браузера (поля, колонтитули); контролюється через `@page` у `print.css`.

**Neutral**
- Готовий `resume.pdf` при збірці можна додати окремою фічею з власним ADR, коли з'явиться потреба.
