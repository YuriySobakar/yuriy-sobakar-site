# 0005 — Кнопка «Share» через Web Share API з копіюванням посилання як запасним варіантом

- **Status:** Accepted
- **Date:** 2026-09-06
- **Deciders:** Yuriy Sobakar (рішення власника в робочій сесії)

## Context

Власник хоче кнопку «поділитися резюме» у правому верхньому куті hero, зручну і з телефона, і з десктопа. Конвенція фундаменту каже: «без клієнтського JavaScript, окрім `window.print()` і лічильника кліків; будь-яка інтерактивність понад це потребує ADR» (карта архітектури §Conventions, `CLAUDE.md` правило 6). Поділитися сторінкою без JavaScript можна лише посиланнями на конкретні мережі (`twitter.com/intent`, `linkedin.com/share`), що нав'язує перелік сервісів і веде трафік до них.

## Decision drivers

- З телефона очікується системний аркуш «Поділитися» (месенджери, пошта, контакти) — це один жест.
- З десктопа найкорисніше отримати посилання в буфер обміну.
- Без cookie, без сховища, без запитів до сторонніх серверів (spec resume-page §6.1).
- Вага в межах бюджету 150 КБ; без бібліотек.

## Considered options

1. **Web Share API + fallback на `navigator.clipboard`** — один делегований обробник кліку в `layout.njk`; на телефоні відкривається системний аркуш, на десктопі копіюється URL і підпис кнопки на 2 секунди стає «Link copied».
2. **Набір посилань на соцмережі без JS** — LinkedIn / X / Telegram / пошта як звичайні `<a href>`.
3. **Стороння бібліотека «share buttons»** — готові віджети.

## Decision outcome

**Chosen:** Option 1. Це єдиний варіант, що дає системний аркуш на мобільному і працює з будь-яким месенджером, а не з обраним переліком. Обробник ~20 рядків, без залежностей, без мережі. Варіант 2 відкинуто: він нав'язує список сервісів і не працює з «поділитися в чат». Варіант 3 відкинуто: зайва вага і сторонні скрипти.

## Consequences

**Positive**
- Одна кнопка на всіх пристроях; на телефоні — рідний аркуш, на десктопі — посилання в буфері з видимим підтвердженням.
- Нічого не зберігається і нікуди не надсилається; тест збірки перевіряє відсутність `fetch`, cookie і сховища в обробнику.

**Negative**
- Це третій дозволений клієнтський скрипт (після `window.print()` і лічильника). Тест збірки фіксує точну кількість `<script>`; наступна інтерактивність знову потребує ADR.
- Без JavaScript кнопка не діє (вона видима, але нічого не робить); прийнято, бо решта сторінки повністю працює без JS.

**Neutral**
- Кнопка схована на папері (`.no-print`), як і «Print».
